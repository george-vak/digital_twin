# Эксперимент №1: GRU на уровнях переменных

Все команды ниже выполняются из корня репозитория. Общий код остаётся в корне.
Данные эксперимента лежат в `exp_1/data/`, сохранённый исторический запуск —
в `exp_1/runs/original/`. Его показатели остаются MAE в физических единицах
для h=1, 5, 10; методику будущего exp_2 к ним задним числом не применяем.

Исторические настройки (h=1, 5, 10 и два теста) сохранены в
`exp_1/runs/original/config.json`. Для новых запусков `exp_1/config.json`
использует только h=1 и test из набора 20_5_5, согласно уточнённой постановке.
Основные команды:

```bash
# Проверить команды без записи файлов и вычислений
python exp_1/run.py --run check_01 --dry-run
# Новая оценка сохранённых моделей, сравнение и графики; без обучения
python exp_1/run.py --run check_01
# Новое обучение h=1, затем оценка и графики
python exp_1/run.py --run repeat_01 --train
# Графики конкретного существующего запуска
python grf.py --run-dir exp_1/runs/check_01 --no-show
```

Каждый запуск получает собственные `models/`, `results/`, `comp/`, `plots/`,
`logs/run.log`, копию `config.json` и `manifest.json` с командами, версиями
пакетов и контрольными суммами кода и входных файлов. Без `--train` веса
копируются из `--source-run original`; это повторная оценка, не новое обучение.
Существующее имя запуска отклоняется; без `--run` создаётся имя с UTC-временем.
Архив пользователя с текстом и выбранными рисунками: `runs/original/reports/`.
Исходные `.pt` сохранены побайтно; исторический путь обучения внутри них
разрешается общим кодом в `exp_1/data/`. Список переноса и контрольные суммы:
`runs/original/migration_manifest.json`.

В `model.py`, `eval.py`, `compare.py`, `grf.py` значения по умолчанию относятся
к историческому exp_1. Для регулярных повторов используйте `exp_1/run.py`:
низкоуровневые eval/compare/grf обновляют отчёты по выбранным путям.

Модель прогнозирует все 53 переменные процесса: 41 измерение `CV` и 12 управляющих воздействий `MV`. 
Архитектура: один слой GRU с 64 скрытыми компонентами `64 → 53`. 
Обучение и оценка работают на CPU через PyTorch.

## Данные и задача прогноза

Обучение использует `exp_1/data/base_20_5/`:

| Выборка | Seeds      | Строк  |
| Train   | 1, 2, 3, 4 | 20 000 |
| Validat | 6          | 5000   |
| Test    | 7          | 5000   |

Одна строка — среднее за 60 секунд симуляции.

При `h=i` целью будет только точка `t+i`, а не последовательность из i следующих точек.

Окна сдвигаются на одну строку и создаются отдельно внутри каждого `run_id`.
Количество окон в прогоне: `N − window − h + 1`. Скрытое состояние GRU начинается
с нуля для каждого окна. При оценке каждое окно содержит фактическую историю;
предыдущие прогнозы обратно на вход не подаются.

Каждый столбец стандартизован: `(x − mean_train) / std_train`, `ddof=0`.
Параметры рассчитаны по всем 20 000 строкам train.
Для постоянного столбца используется масштаб 1.
Идентификатор прогона и время не входят в признаки модели.

## Установка и обучение

Из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 exp_1/run.py --run repeat_01 --train
```

Обучение: Adam, learning rate `0.001`, batch size `256`, MSE по нормализованным
переменным, ограничение нормы градиента `1.0`, seed `42`. Максимум 30 эпох; 
остановка после 5 эпох без улучшения validation MSE. Сохраняется модель с
минимальной validation MSE.

- `exp_1/runs/<имя>/models/*.pt` — веса, архитектура и параметры обучения.
- `exp_1/runs/<имя>/models/*.history.csv` — train/validation MSE по эпохам.


Для другого горизонта переобучение например

```bash
python3 model.py --horizon 5 --run-dir exp_1/runs/h5_repeat
```

Значения по умолчанию явно заданы в `model.py`: `WINDOW=60`, `HORIZON=1`.
Также доступны `--data`, `--hidden-size`, `--epochs`, `--patience`, `--batch-size`,
`--lr`, `--seed`. `--output`

Существующий checkpoint не перезаписывается. Для нового обучения используйте `python exp_1/run.py --run <имя> --train` либо новый `--run-dir` / `--output` у model.py.

## Генерация датасетов: generate.py

### Подготовка и общий вид команды

Активировать окружение:

```bash
source .venv/bin/activate
```

`generate.py` сам запускает контейнер Linux x86-64 с симулятором

```bash
python3 generate.py [параметры]
python3 generate.py --h
```

Скрипт сохраняет нормализованные временные ряды в `exp_1/data/<dataset>/` рядом с кодом
проекта. Он не создаёт временные окна. 

### Все параметры и значения по умолчанию

| Параметр | По умолчанию | Что задаёт |

| `--dataset`    | `base_20_5` | Имя новой папки внутри `exp_1/data/`. Имя но не полный путь.
| `--experiment` | `exp_1` | Папка эксперимента внутри репозитория; данные сохраняются в её `data/`.
| `--freq`       | `60s`       | Интервал одной выходной строки. `60s`, `5min`. Значения процесса усредняются за этот интервал.
| `--tr-dur`     | `20000min`  | Общая длительность симуляции для train, суммарно по всем его seeds.
| `--val-dur`    | `5000min`   | Общая длительность симуляции для validation.
| `--test-dur`   | `5000min`   | Общая длительность симуляции для test.
| `--tr-seeds`   | `1,2,3,4`   | Seeds отдельных прогонов train, перечисленные через запятую без пробелов.
| `--val-seeds`  | `6`         | Seeds прогонов validation.
| `--test-seeds` | `7`         | Seeds прогонов test. Для нового независимого теста выбрать не использованную.
| `--tonly`      | Выключен    | Флаг без значения: генерирует только test и файлы описания. Требует `--nrm`.
| `--nrm`        | Не задан    | Путь к существующему `normalization.json`. Без него при полной генерации параметры рассчитываются по новому train. Если задан, все создаваемые выборки используют загруженные параметры без повторного расчёта.
| `--chunk`      | `1000`      | Сколько выходных строк запрашивать за один вызов симулятора. Прогон продолжается между вызовами; это не длина окна модели.
| `-h`, `--h`    | — | Показывает справку и завершает работу без запуска Docker.


### Пример: полный датасет с настройками по умолчанию

```bash
python3 generate.py --dataset normal_v2
```

Получится 20 000 строк train (по 5000 на seeds `1,2,3,4`), 5000 строк validation
(seed `6`) и 5000 строк test (seed `7`). Шаг — 60 секунд.
Нормализация рассчитывается только по новому train и применяется ко всем выборкам.

Папка `exp_1/data/normal_v2/` будет содержать:

| Файл | Содержимое |
| `train.csv.gz`       | Обучающие временные ряды.
| `validation.csv.gz`  | Валидационные временные ряды.
| `test.csv.gz`        | Тестовые временные ряды.
| `normalization.json` | Среднее и масштаб каждого признака.
| `variables.csv`      | Названия, описания и физические единицы переменных.
| `metadata.json`      | Частота, seeds, длительности, число строк и способ предобработки.

`.csv.gz` — сжатый CSV; распаковывать его для обучения и оценки не требуется.


### Пример 2: новый тест на 2000 строк для существующей модели

```bash
python3 generate.py --dataset test_2k_seed9 --tonly \
  --test-seeds 9 --test-dur 2000min \
  --nrm exp_1/data/base_20_5/normalization.json
```

Получится `exp_1/data/test_2k_seed9/test.csv.gz`: один прогон seed `9` на 2000 строк
с шагом 60 секунд. Рядом сохранятся три файла описания: `normalization.json`,
`variables.csv`, `metadata.json`. Файлы train и validation не создаются.

Параметры нормализации берутся из исходного обучающего датасета.
Частота тестовых данных должна совпадать с частотой обучения модели.

## Оценка модели: eval.py

### Подготовка и общий вид команды

Активировать `.venv`. Docker для оценки не нужен. Модель уже должна быть обучена:
`eval.py` загружает существующий `.pt`, строит окна из переданного файла и считает MAE.

```bash
python3 eval.py [file] [--model PATH] [--output PATH]
```


### Все параметры и значения по умолчанию

| Параметр | По умолчанию | Что задаёт |
| `file`         | `exp_1/data/base_20_5/test.csv.gz`    | Файл для оценки: `.csv` или `.csv.gz`.
| `--model`      | Не задан                        | Явный путь к `.pt` обязательно.
| `--output`     | Автоматическое имя в `exp_1/runs/original/results/` | Полный путь к CSV-отчёту, включая имя файла.
| `-h`, `--help` | — | Показывает справку и завершает работу без оценки.


### Пример: текущий test и модель h=5

Если такой модели ещё нет, сначала обучить её. Затем запустить оценку:

```bash
python3 eval.py --model exp_1/runs/original/models/gru_h5.pt
```

Для одного прогона на 5000 строк при окне 60 и `h=5` получится 4936 прогнозов.

### Пример 2: новые 2000 строк и модель h=5

После генерации `test_2k_seed9` командой выше:

```bash
python3 eval.py exp_1/data/test_2k_seed9/test.csv.gz --model exp_1/runs/original/models/gru_h5.pt
```

Отчёт: `exp_1/runs/original/results/gru_h5_test_2k_seed9_test.csv`. Оценка содержит 1936 прогнозов:
`2000 − 60 − 5 + 1`. Для двух прогонов по 2000 строк будет `2 × 1936 = 3872`
прогноза, поскольку начало каждого прогона отдельно используется как история.


### Требования к входному файлу и нормализация

CSV без `metadata.json` считается данными в исходных физических единицах. 
Нормализованный файл нельзя переносить отдельно от его описания.
Нужны все столбцы: `run_id`, `step`, `elapsed_seconds`, `CV[0]…CV[40]`,
`MV[0]…MV[11]`. Частота должна совпадать с частотой обучения; внутри каждого
прогона шаги и время должны идти без пропусков и дубликатов.
В каждом прогоне должно быть минимум `window + horizon` строк.


### Что находится в результате

1. В начале описание запуска и модели.
2. Затем таблица для всех 53 переменных.


## Сравнение с прогнозом последним значением

`baseline.py` содержит `PersistenceModel`: для входного окна `t−L, …, t`
модель возвращает последнюю строку `x[t]` как прогноз на `t+h`.
Для `h>1` используется именно `x[t]`: значение `x[t+h−1]` на момент прогноза
ещё неизвестно.

`compare.py` читает готовый CSV-отчёт GRU и оценивает baseline на том же файле,
с тем же окном, горизонтом, частотой и целевыми точками. Внутри каждого `run_id`
окна строятся отдельно. MAE GRU берётся из отчёта, повторного запуска GRU при
сравнении нет.

```bash
python3 compare.py exp_1/runs/original/results/gru_h5_base_20_5_test.csv --output exp_1/runs/original/comp/my_comparison.csv
```

| Параметр compare.py | По умолчанию | Назначение |
| `report`            | Обязателен | Путь к CSV-отчёту, созданному `eval.py`.
| `--output`          | `exp_1/runs/original/comp/comparison_<имя отчёта>.csv` | Путь к итоговому CSV. Без переопределения — comp/ того же запуска, что и входной отчёт.
| `-h`, `--help` | — | Показать справку.

Все сравнения по умолчанию сохраняются в отдельную папку `exp_1/runs/original/comp/`.
Повторное сравнение того же отчёта заменяет соответствующий файл.
В начале CSV сохраняются краткие сведения об оценке GRU и число переменных,
по которым GRU лучше, хуже или имеет равную MAE. Контрольные суммы проверяются программой, но
в пояснениях сравнения не выводятся.
Последняя строка перед таблицей — `Среднее изменение по группам`: отдельно
среднее процентное снижение MAE среди переменных с улучшением и средний
процентный рост MAE среди переменных с ухудшением. У каждой переменной одинаковый
вес. Указано число переменных в каждой группе. Равные ошибки в эти группы не
входят; переменные с нулевой MAE baseline исключены из процентного расчёта
и подсчитаны отдельно.
Это описание двух групп, а не единый процент улучшения всей модели.
Средние проценты чувствительны к переменным с очень маленькой ошибкой baseline.
Далее идёт таблица. Положительное улучшение означает, что GRU лучше, отрицательное — хуже.
При нулевой MAE baseline процент не определён: в CSV будет `—`, а абсолютная
разница и обе ошибки сохраняются. Общая MAE по разным физическим величинам
не усредняется.

Служебный JSON в `.metaexp_1/data/` хранит SHA256 модели, самого отчёта и входных
данных, включая `metadata.json` и используемый файл нормализации.
`compare.py` сверяет эти суммы перед расчётом.

Папка `tests/` содержит автоматические проверки кода, а не тестовые датасеты.
Они проверяют сопоставление окон, формулы, нулевую ошибку, контрольные суммы,
формат отчёта и CLI. Запуск:

```bash
python3 -m unittest discover -s tests -v
```

## Графики

```bash
python grf.py --run-dir exp_1/runs/original
```

Создаются количество улучшившихся/ухудшившихся переменных, тепловая карта
снижения MAE и отдельные листы гистограмм остатков всех 53 переменных для
h=1 на каждом тесте. Для остатков выполняется инференс по сохранённым весам;
пересчитанная MAE сверяется с CSV. `--no-show` сохраняет PNG без открытия окон.
Остаток определён как прогноз минус факт; все текущие ошибки — в исходных
физических единицах. Графики сохраняются в `plots/` соответствующего запуска.
