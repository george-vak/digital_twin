# Удержание цены 160 при ограничениях CV

Финальная модель после подбора гиперпараметров находится в `runs/controller.pt`. Выбранные параметры записаны в `config.json`, текущий запуск указан в `current_run.json`. В `results_summary.json` и `краткий_вывод.md` собраны его результаты. В папке оставлен только последний финальный запуск; старые запуски и промежуточные файлы поиска удалены.

## Постановка

Актёр должен как можно дольше поддерживать цену около 160 при допустимых CV. Максимальная длительность эпизода составляет 200 шагов по 60 секунд. Границы каждого CV равны P1 и P99 его значений за 1000 шагов прогрева соответствующего эпизода. MV[0]–MV[10] ограничены диапазоном 0–100, постоянная MV[11] исключена из обучаемых входов и выходов и сохраняет значение прогрева.

Проверка CV выполняется сразу после прогрева и после каждого шага. Нарушение хотя бы одного ограничения завершает эпизод. Начальное нарушение даёт эпизод с нулём шагов и отсутствующими метриками цены (`null`). Для сравнения с границами используется допуск на округление float32. Замерший симулятор также завершает эпизод. Достижение 200 шагов при соблюдении ограничений считается завершением по лимиту. Команды после окончания эпизода отклоняются до следующего `reset`.

## Обучение

Веса актёра и модели динамики, а также исторические переходы берутся из exp_4. История состоит из 60 разностей CV/MV. Модель динамики обучается по фактическим переходам, включая последний переход с нарушением. В исторический replay включена история прогрева перед первым действием, что позволяет использовать ранние безопасные состояния. Для обучения актёра выбираются только состояния внутри границ. При малом числе таких состояний выборка выполняется с возвращением.

В обучении актёра модель динамики фиксируется. Через неё строится дифференцируемый прогноз оставшейся части эпизода вплоть до 200 шагов. Прогнозные состояния возвращаются на вход модели и актёра. Для каждого шага рассчитываются плавная оценка сохранения всех ограничений и близость прогнозной цены к 160.

```text
quality[t] = exp(-((cost[t] - 160) / cost_scale)^2)
survival[t] = product(probability[0:t+1])
expected_safe_steps = sum(survival[t])
tracking_return = sum(survival[t] * quality[t])
actor_loss = -survival_weight * expected_safe_steps
             -tracking_weight * tracking_return
             +regularization_weight * window_penalty
             +barrier_weight * (cv_barrier + mv_barrier)
```

Вес безопасной длительности равен 1, выбранный вес близости цены равен 0.3, масштаб ошибки цены равен 10. Каждый фактически безопасный шаг получает награду `1 + tracking_weight * quality`, терминальный шаг с нарушением или замершим симулятором получает 0. Будущее после завершения отсутствует. Дисконтирование отсутствует. В логах `reward` отражает фактический результат, а градиент актёра рассчитан через прогноз модели. Поле `actor_tracking_loss` хранит одношаговую MSE цены для диагностики. В оптимизируемую сумму входит накопленный `actor_tracking_objective`.

Плавная оценка ограничений равна сигмоиде минимального нормированного запаса CV до границы с выбранной температурой 0.1. Для постоянных CV используется масштаб 0.001, фактический барьер при этом остаётся точечным. Эта оценка служит дифференцируемым приближением. Её вероятностная калибровка отдельно не проверена. Прогноз обрывается досрочно, когда накопленная оценка выживания всех элементов batch ниже 1e-6. Максимальный пропущенный вклад в ожидаемые безопасные шаги ограничен 0.0002 на элемент.

Оконная регуляризация использует 10 последних MV с весом 100. Барьерный штраф имеет вес 1. Скорость обучения актёра равна 3e-5, модели динамики — 1e-4, размер batch — 64. Перед взаимодействием с симулятором выполняются 32 совместных обновления актёра и динамики, затем по одному на каждый новый переход. Эти значения выбраны по валидации.

## Метрики

В результатах отдельно сохраняются выполненные шаги, безопасные шаги, безопасные шаги при цене 160 ± 5, самая длинная непрерывная серия таких шагов, количество эпизодов до 200 шагов и причины остановки. Допуск ±5 выбран для отчётной метрики. Обучение использует плавную награду с выбранным масштабом отклонения 10.

Средняя длительность учитывает все эпизоды, включая нулевые. Средняя цена, MAE и RMSE рассчитываются по фактически выполненным переходам, включая терминальный. Веса переходов одинаковы. Нулевые эпизоды входят в статистику длительности и не дают наблюдений цены. Проверка ограничений относится к минутным наблюдениям, межшаговые нарушения отдельно не отслеживаются.

## Повторный запуск

Текущие результаты лежат непосредственно в `runs/`, кэш обучения — в `data/`, отчёты о подборе — в `reports/`. Команда `.venv/bin/python -m exp_7.summarize` проверяет текущие результаты и обновляет краткий вывод. У `run.py` и `plot.py` отсутствие `--run` также означает текущий каталог `runs/`; существующие результаты защищены от перезаписи.

Из корня проекта при работающем Docker с образом `temain-simulator:local` выполните команды с новым именем запуска.

```bash
.venv/bin/python exp_7/run.py --run repeat_01
.venv/bin/python exp_7/run.py --run repeat_01 --phase validation
.venv/bin/python exp_7/run.py --run repeat_01 --phase evaluation
.venv/bin/python -m exp_7.summarize --run repeat_01
.venv/bin/python -m unittest discover -s tests
```

Финальное обучение использует seed симулятора 600–629 и seed обучения 45, валидация 700–719, оценка 900–919. На валидации и оценке веса фиксированы. Существующие каталоги запусков защищены от перезаписи. В каждом этапе сохраняются конфигурация, прогревы, границы, переходы, сводка и графики. Для нулевого эпизода график CV/MV показывает начальное состояние.


## Подбор гиперпараметров

Для подбора использован `tune.py`. Протокол, диапазоны и критерий выбора находятся в `reports/protocol.json`, сводная таблица результатов — в `reports/comparison.csv`, выводы и сравнение на новых оценочных seed — в `reports/report.md`. Повторный запуск обучения с уже выбранными параметрами описан выше; заново запускать подбор для этого не требуется.

Первый этап проверяет 24 набора на 10 обучающих и 10 валидационных эпизодах. Поиск охватывает скорости обучения актёра и динамики, batch, шум, окно и вес регуляризации, вес и epsilon барьера, вес близости цены, масштаб ошибки цены, температуру оценки границ, объём предварительного обучения и число обновлений на шаг.

Три лучших набора проверяются повторно с seed обучения 43 и 44, бюджетами 10 и 30 обучающих эпизодов и 20 валидационными эпизодами. Всего выполнено 12 подтверждающих запусков. Выбор максимизирует среднее число безопасных шагов при 160 ± 5, затем общую безопасную длительность, затем близость цены на безопасных шагах с единым масштабом 10. При равенстве используется MAE. Критерий сравнения одинаков для всех вариантов.

После фиксации выбора финальная модель дообучается из исходных весов exp_4 с seed 45. Evaluation использует новые seed 900–919. Для сравнения прежняя модель также оценена на этих начальных условиях. Конфигурация по умолчанию обновляется выбранными значениями.

Предварительное обучение использует общий проверяемый кэш 644 исторических переходов, из которых 21 начинается внутри границ CV. Кэш содержит хеши источников. При несовпадении источников обучение отклоняет его. Параметр `--no-plots` позволяет выполнять поисковые запуски без построения графиков. Для финального запуска графики сохранены для всех эпизодов.

Поиск ограничен перечисленными диапазонами. После очистки сохранены итоговые таблицы, графики сравнения, протокол и выбранные параметры. Полные траектории старых вариантов и временные логи удалены. В `runs` сохранены веса, данные и графики обучения, валидации и итоговой оценки. Кэш `data/parent_replay.npz` необходим для повторного обучения по текущей конфигурации; исходный `base_config.json` сохранён для воспроизводимости протокола поиска. Исторические имена запусков в таблицах и протоколе описывают выполненный подбор, их каталоги больше не хранятся.
