# Поканальная регуляризация управления

Запуск из корня проекта:

```bash
.venv/bin/python exp_4/run.py --run first
```

На macOS нужен работающий Docker с образом `temain-simulator:local`.
Результаты сохраняются в новую папку `exp_4/runs/<имя>/`.
Для другого набора параметров используйте `--config путь/к/config.json`.

Актёр, модель CV, нормализация, стоимость и симулятор используются из `exp_3`.
Цикл обучения и построение графиков адаптированы в `exp_4`; исходный `exp_3`
не изменяется. Обучение начинается с того же checkpoint из `exp_2`, как в базе.

## Регуляризация

Для каждого MV отдельно вычисляется среднее последних `regularization_window`
наблюдаемых абсолютных значений, включая текущее. Используется история именно
выбранного перехода replay buffer до применения его новой команды, без будущих
наблюдений и без смешивания эпизодов. Начальное окно берётся из прогрева.

```text
reference[j] = mean(last W observed MV[j])
actor_penalty = mean_over_batch_and_channels(((actor_action - reference) / scale)^2)
actor_regularization = weight * actor_penalty
actor_loss = actor_cost + actor_regularization
```

Штраф применяется к ограниченной диапазоном [0, 100] команде актёра до
исследовательского шума. Опорное среднее не получает градиентов.
Обучение модели CV и фактическая стоимость симулятора остаются прежними.
Возврат к дефолтным управлениям не реализован.

Параметры в `config.json`:

- `regularization_window: 60` — число последних наблюдений MV; допустимо от 1
  до длины доступной истории уровней (окно модели + 1).
- `regularization_scale: 100.0` — масштаб отклонений в процентных пунктах MV,
  одинаковый для всех 12 каналов.
- `regularization_weight: 1.0` — начальный, ещё не подобранный коэффициент.
  Его влияние зависит от масштаба прогнозной стоимости. Значение 0 отключает
  вклад штрафа и позволяет сравнить с базовым обучением.

В `steps.csv` отдельно записываются `actor_cost` (прогнозная стоимость на batch),
`actor_penalty` (штраф без коэффициента), `actor_regularization` (взвешенный штраф)
и `actor_loss` (сумма). До начала обновлений эти поля пустые.
`predicted_cost` — отдельный прогноз для фактически поданной команды с шумом.
Конфигурация сохраняется и рядом с результатами, и внутри `controller.pt`.

## Графики

Автоматически создаются только `01_training.png`, `03_cv_episode_*.png`
и `04_mv_episode_*.png`. График 1 показывает фактическую стоимость без штрафа.

```bash
.venv/bin/python exp_4/plot.py --run first
.venv/bin/python exp_4/plot.py --run first --episode 0
```
