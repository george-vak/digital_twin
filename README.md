# Эксперименты с прогнозированием технологического процесса

Общий код находится в корне. Данные, настройки и результаты каждого
эксперимента хранятся в `exp_i`; повторные запуски — в `exp_i/runs/<имя>/`.

```text
digital_twin/
├── model.py                 # GRU, окна, обучение
├── generate.py              # Генерация через симулятор
├── eval.py                  # Оценка сохранённой модели (протокол exp_1)
├── baseline.py / compare.py # Прогноз последним значением и сравнение
├── grf.py                   # Графики MAE и остатков
├── preprocess.py            # Разности и стандартизация для exp_2
├── evaluate_mase.py          # Сравнение exp_1 и exp_2 на общих целях
├── experiment_paths.py      # Общие правила путей
├── experiment_runner.py     # Изолированные запуски экспериментов
├── temain.py / libtemain.so / Dockerfile
├── requirements.txt
├── tests/
├── exp_1/
│   ├── README.md / config.json / run.py
│   ├── data/                # Train, validation и два test; нормализация
│   └── runs/
│       ├── original/        # Перенесённые результаты первого эксперимента
│       │   ├── models/     # Веса и история обучения h=1, 5, 10
│       │   ├── results/    # MAE и служебные .metadata/
│       │   ├── comp/       # Сравнение с persistence
│       │   ├── plots/
│       │   ├── reports/    # Пользовательский текст и рисунки отчёта
│       │   └── migration_manifest.json
│       └── <новый_запуск>/ # Результаты + config.json, manifest.json, logs/
└── exp_2/
    ├── README.md / config.json / run.py
    └── runs/<имя>/          # Производные данные, веса, MASE, графики и отчёт
```

Установка из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Повторная оценка сохранённой модели h=1 первого эксперимента, сравнение с
эталоном и все графики в новой папке, без переобучения:

```bash
python exp_1/run.py --run check_01
```

Для нового обучения h=1 и последующей оценки на наборе 20_5_5:

```bash
python exp_1/run.py --run repeat_01 --train
```

Имена запусков должны быть новыми. `--dry-run` показывает команды без
выполнения; `--source-run <имя>` выбирает сохранённые модели для повторной
оценки. Без `--run` имя создаётся автоматически. Лог, снимок настроек,
версии пакетов и контрольные суммы сохраняются внутри запуска. Неудавшийся
запуск помечается `failed`, успешно выполненный — `complete`.

Графики исторического запуска, без открытия окон:

```bash
python grf.py --run-dir exp_1/runs/original --no-show
```

Создание нового набора данных (требуется Docker с Linux x86-64):

```bash
python generate.py --experiment exp_1 --dataset normal_v2
```

Артефакты используют пути относительно корня репозитория, поэтому перенос
проекта и запуск из другой рабочей папки не ломают ссылки. Исключение —
исторический путь внутри исходных `.pt`: веса оставлены без изменений,
а путь отображается через `experiment_paths.py`. Данные не пересоздавались.

Проверки:

```bash
python -m unittest discover -s tests -v
```

Подробности: [эксперимент №1](exp_1/README.md),
[эксперимент №2](exp_2/README.md).

Эксперимент №2 выполнен в `exp_2/runs/first`: одно обучение на разностях и сравнение с сохранённой exp_1
при h=1 на наборе 20_5_5. MASE ± std считается по общим тестовым точкам,
отдельно для каждой переменной. Пять повторов обучения не выполняются.

```bash
python exp_2/run.py --run recheck --source-run first
```

Команда выше повторяет оценку уже обученных моделей. Для нового обучения
нужны новое имя запуска и `--train`. Исторические отчёты MAE первого
эксперимента сохраняются.
